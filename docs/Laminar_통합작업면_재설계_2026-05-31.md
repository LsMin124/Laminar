# Laminar 통합 작업면 재설계 (2026-05-31)

> 구상안(`Laminar_Spec.md` v5.1)의 정체성과 현재 프론트 구현의 격차를 좁히기 위한
> **작업면 정보구조 · 직접조작 모델** 설계. 백엔드 도메인/API는 유지·재사용한다.
> 구현 전 합의용 — 합의 후 단계적으로 구축한다.

## 0. 문제 정의

현재 산출물은 **6엔티티 백엔드(카드·화살표·그룹·그룹화살표·탭·영구노트 + 관계/버전/장비 API)는 제대로 구축**되어 있으나, 프론트가 구상안의 핵심인 *"한 화면에서 카드·화살표·그룹·탭을 직접 조작하는 캘린더-캔버스"*가 아니라 **엔티티별 목록·폼·정적 뷰를 페이지로 나눈 일반 CRUD 앱**으로 구현되었다. 즉 데이터·기능은 있으나 *엮어서 조작하는 경험*(제품의 정체성)이 빠졌다.

## 1. 구상안 정체성 (Spec §0·§3·§4 재확인)

- **Personal-First**: 개인 도구 + 공용 자원만 팀 공유. 다른 사용자 카드 불가시(자동 검증).
- **6엔티티, "모든 것이 노트(row)이고 관계조차 노트"**: 카드 / 화살표 / 그룹 / 그룹화살표 / 탭 / 영구노트.
- **캘린더-우선 + 멀티데이 카드**: 시작/종료일 있으면 자동 배치. *카드 표면에서 직접* 날짜·todo·summary·GCal 토글 조정(모달 없이).
- **화살표 그리기 → 그룹 자동 형성**: 두 카드를 이으면 직사각형 그룹 자동 생성. 양쪽이 다른 그룹이면 *흡수 모달*, 화살표 삭제로 끊기면 *유지/분리 모달*.
- **그룹 화살표 = 거시 흐름**, **탭 = 중기목표 트리**(visible 부모가 후손을 흡수 → *줌인/아웃*; 트리 + 탭 화살표 DAG).
- **영구노트** = 시간축 밖 참조 + `perpetual-ver` 버전 마커(git diff: 현재 vs 시점). 사이드바 상시 트리.
- **공용 장비 캘린더**: 드래그 예약 + 충돌검증 + log/공지(`equipment_admin`).
- **GCal 알림 위임**(자체 푸시 없음).

## 2. 현재 격차 (구상안 → 실제)

| 구상안 핵심 UX | 실제 구현 | 격차 |
|---|---|---|
| 캘린더-우선 + 카드 표면 인라인 편집(모달 없이) + 날짜 `+` + 드래그 일정 | `MonthGrid` + 셀 클릭 → **모달 폼**(`CardForm`) | 드래그·인라인 없음 |
| 화살표 그리기 → 그룹 자동 형성(흡수/분할 모달) | `BoardGraph` **읽기전용**(클릭=상세 이동) + `GroupManager` 폼 | 캔버스 조작 핵심 부재 |
| 탭 = 중기목표 트리 + visible 흡수 줌인/아웃(보드 조직 골격) | 보드엔 calendar/graph **뷰 토글**만, 탭 트리 없음(영구노트 페이지에만) | 보드 골격 누락 |
| 영구노트 사이드바 상시 트리 + git diff | 별도 `PerpetualPage` | 통합 안 됨 |
| 통합 단일 작업면 | 보드·카드상세·영구·멤버·장비 **다중 페이지** | 캔버스감 상실 |

## 3. 타깃 정보구조 — 단일 보드 작업면

**하나의 보드 = 하나의 통합 작업면.** 페이지 이동을 최소화하고, 카드/영구노트/그룹 편집을 작업면 내 *패널·인스펙터*로 흡수한다.

```
┌──────────────────────────────────────────────────────────────┐
│ 보드 헤더 (이름 · 줌 컨텍스트(현재 탭) · 보기 전환 · 멤버/장비 진입)   │
├───────────────┬──────────────────────────────┬───────────────┤
│ 좌 사이드바     │  메인 렌즈                      │ 우 인스펙터     │
│  ┌──────────┐ │  ┌────────────────────────┐  │ (선택 카드/노트) │
│  │ 탭 트리   │ │  │  캘린더 렌즈  /  캔버스 렌즈 │  │  인라인 편집     │
│  │ (중기목표) │ │  │  (같은 카드 모델의 두 시점) │  │  + 첨부/관계/버전 │
│  ├──────────┤ │  │                        │  │               │
│  │ 영구노트  │ │  │                        │  │               │
│  │ 트리      │ │  └────────────────────────┘  │               │
│  └──────────┘ │                              │               │
└───────────────┴──────────────────────────────┴───────────────┘
```

- **메인 렌즈**: 캘린더와 캔버스를 *모드 전환*이 아니라 *같은 카드 모델 위의 두 렌즈*로 본다. 선택·호버·필터 상태를 공유. (MVP: 전환 유지하되 상태 공유 → 장기: 분할/오버레이 검토 — §7 결정)
- **좌 사이드바**: 탭 트리(보드 조직·줌) + 영구노트 트리(상시). 접기 가능.
- **우 인스펙터**: 선택된 카드/영구노트를 *작업면을 떠나지 않고* 인라인 편집. 기존 `CardDetailPage`·`CardForm`을 흡수.

## 4. 상호작용 모델 (직접조작)

### 4.1 캘린더 렌즈
- 날짜 셀 hover → `+`로 **인라인 카드 생성**(제목만 입력, 시작일 자동). 모달 아님.
- 카드 막대 **드래그 → 일정 이동**, 끝단 드래그 → 기간 조정(멀티데이).
- 카드 표면 미니 컨트롤: 완료 토글·중요도 점·GCal 토글·summary. 본문 편집은 인스펙터.

### 4.2 캔버스 렌즈
- 카드 노드 **드래그 배치**(좌표 저장 — §7 백엔드 결정).
- 카드 핸들에서 드래그해 다른 카드에 놓으면 **화살표 생성 + 그룹 자동 형성**. 양쪽이 다른 그룹이면 **흡수 모달**(어느 그룹이 흡수할지).
- 화살표 삭제로 그룹이 끊기면 **유지/분리 모달**(멤버 ≤1은 자동 삭제).
- 그룹 = 직사각형 컨테이너(드래그·리네임). 그룹 핸들 → **그룹 화살표**.
- 선택/호버는 캘린더 렌즈와 동기화.

### 4.3 탭 트리 (좌 사이드바)
- 탭 트리(드래그 재배치) + 탭 화살표(DAG, 시간순).
- **visible 부모 = 후손 카드를 흡수한 단일 섹션 / hidden 부모 = 후손 탭 개별 노출** → 사용자가 목표 단위로 **줌인/아웃**. 선택 탭 범위로 메인 렌즈가 필터.

### 4.4 영구노트 (좌 사이드바)
- 트리 상시 표시. 노트 선택 → 인스펙터에 본문 + **버전 이력**.
- 편집 시 *직전 baseline*이 `perpetual-ver` 카드로 자동 저장(캘린더에 그 시점 배치). 클릭 시 *현재 vs 시점* diff.

### 4.5 공용 장비 (워크스페이스 레벨 — 보드 밖)
- 별도 작업면. 장비 캘린더 드래그 예약 + 충돌검증 + log/공지. 현 `EquipmentPage` 재활용·강화.

## 5. 컴포넌트 아키텍처

**재사용(백엔드 API 변경 없음)**: boards · cards(+calendar/graph) · card-relations · groups · group-relations · tabs · tab-relations · perpetual-notes/columns/versions · attachments · equipment/reservations · audit/admin.

**신규/재작성(프론트)**:
- `BoardWorkspace` — 셸 레이아웃(좌 사이드바 + 메인 렌즈 + 우 인스펙터), 선택/줌 상태 보유.
- `TabTreeSidebar` — 탭 트리 + visible 흡수 줌.
- `PerpetualSidebar` — 영구노트 트리 + diff 뷰.
- `CalendarLens` — 인라인 생성 + 드래그 일정 + 멀티데이(기존 `MonthGrid` 확장).
- `CanvasLens` — 노드 드래그 + 화살표 그리기 → 그룹 자동형성 + 그룹 컨테이너(기존 읽기전용 `BoardGraph` 대체).
- `CardInspector` — 인라인 편집(기존 `CardDetailPage`/`CardForm` 흡수).
- 모달: 그룹 흡수/분할, 화살표 본문 편집.

**흡수/정리**: `BoardsPage`(목록은 유지) · 별도 `CardDetailPage`·`PerpetualPage`·calendar/graph 토글 → 작업면 내 패널/렌즈로.

## 6. 단계적 구현 순서 (합의 후)

| 단계 | 내용 | 배포·검증 |
|---|---|---|
| P1 | `BoardWorkspace` 셸 + `CardInspector`(카드 인라인 편집, 페이지 이동 제거) | 카드 선택→인스펙터 편집 |
| P2 | `CalendarLens` 직접조작(인라인 생성 + 드래그 일정 + 멀티데이) | 드래그로 일정 변경 |
| P3 | `CanvasLens` 직접조작(노드 드래그 + 화살표 그리기 → 그룹 자동형성 + 흡수/분할 모달) | 화살표→그룹 자동 |
| P4 | `TabTreeSidebar`(탭 트리 + visible 흡수 줌인/아웃) | 줌 단위 필터 |
| P5 | `PerpetualSidebar`(트리 + perpetual-ver diff) | 시점 diff |
| P6 | 공용 장비 작업면 강화 | 드래그 예약 |

## 7. 결정 필요 (open questions)

1. **캔버스 좌표 저장**: 현재 `BoardGraph`는 auto-layout(좌표 비저장). 드래그 배치를 영속하려면 카드(보드 내) `x,y` 좌표 저장 필드가 필요 → **백엔드/DB 추가**(엔티티 컬럼 또는 board-layout). 자동배치 유지 vs 수동배치 영속 결정.
2. **캔버스 구현 방식**: 직접 SVG/포인터 구현 vs `react-flow` 등 라이브러리(번들↑·빠름). "직사각형 그룹 컨테이너 + 화살표 자동그룹"은 커스텀 로직이 많아 헤드리스 + 직접 구현이 더 맞을 수 있음.
3. **캘린더↔캔버스 동시 표시**: MVP에 분할 화면 vs 전환 유지(선택·상태 공유)?
4. **줌인/아웃 반영 방식**: 탭 visible 흡수가 메인 렌즈를 어떻게 필터/집계할지 합의.

## 8. 비범위 (Spec §9 유지)

Canvas(화이트보드)·수식 화살표·AI(Gemini)는 **Phase 2**. 본 재설계는 MVP 6엔티티 직접조작 작업면에 한정한다. 성능/보안 항목(N-1 등)은 사용자 지시로 후순위.
