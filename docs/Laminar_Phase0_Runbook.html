셋업 절차 서비스별 단계 · 클릭으로 펼침

2.1Fly.io — 앱 생성🔸
  1. fly.io 가입 → fly auth login (브라우저 인증)
  2. 앱 생성:
    fly apps create laminar-prod --org personal
    호스트네임 laminar-prod.fly.dev 확정 — OAuth redirect·CORS의 기준값.
  3. 리전: fly regions set은 flyctl 0.4.x에서 deprecated. fly.toml의 primary_region = "nrt"로 지정 (Phase 1 Task 1.8).
  4. ⚠ 결제 카드 (보류 중): 앱 생성은 카드 없이 되지만 첫 배포는 카드 필요. Fly 대시보드 → Billing. Phase 12 배포 전까지 처리.
.env 기록: 없음 (앱 이름·도메인은 코드/fly.toml)
2.2Neon Postgres✅
  1. neon.tech 가입 → 프로젝트 생성, 리전 ap-southeast-1
  2. 기본 branch + DB neondb 자동 생성
  3. 대시보드 → Connect → 연결 문자열 2종:
    • Pooled (호스트 -pooler 포함) → DATABASE_URL
    • Direct (Pooled OFF) → DATABASE_URL_DIRECT
  4. citext 확장 활성화 — Neon 콘솔 SQL Editor:
    CREATE EXTENSION IF NOT EXISTS citext;
⚠ JDBC URL 함정: Neon이 주는 URL은 postgresql://user:pass@host/db?...&channel_binding=require (libpq 형식). 그대로 jdbc: 접두사만 붙이면 pgjdbc가 거부함 — user:pass@host 인증과 channel_binding 키 모두 인식 못함. 해결: .env에 URL은 jdbc:postgresql://host/db?sslmode=require 형식, USERNAME·PASSWORD 별도 분리.
.env 기록 (4종): DATABASE_URL · DATABASE_URL_DIRECT · DATABASE_USERNAME · DATABASE_PASSWORD
2.3Cloudflare R2✅
  1. 대시보드 → R2 Object Storage → Enable R2 (카드 등록 필요)
  2. Create bucket: laminar-prod-attachments, Location APAC
  3. 버킷 Settings → Object versioning → Enable
  4. R2 메인 → Manage R2 API Tokens → Create: Object Read & Write, 버킷 한정 → Access Key + Secret (1회 표시)
  5. Account ID: R2 개요 페이지 우측 → endpoint 구성에 필요
.env 기록 (5종): R2_ACCOUNT_ID · R2_ACCESS_KEY_ID · R2_SECRET_ACCESS_KEY · R2_BUCKET · R2_ENDPOINT
※ R2_ENDPOINT = https://<R2_ACCOUNT_ID>.r2.cloudflarestorage.com — placeholder 실제 ID로 치환 필수
검증: R2_ENDPOINT에 HTTPS GET → HTTP 400 InvalidArgument: Authorization = 정상.
2.4Resend — API 키만🔸
  1. resend.com 가입 (도메인 추가는 건너뜀)
  2. API Keys → Create: Name laminar-prod, Permission Sending access, Domain All Domains → re_... 키 1회 표시
⚠ 도메인 검증 보류 중 (§12.3.1 v3 정책): 미검증 상태에서 email_outbox.last_error='no_domain_verified' 마킹만 하고 발송 보류. 가입 이메일 주소로만 테스트 가능.
.env 기록: RESEND_API_KEY
2.5Google Cloud — OAuth 클라이언트✅
  1. console.cloud.google.com → 프로젝트 laminar-prod 생성
  2. APIs & Services → Library → "Google Calendar API" → Enable
  3. OAuth consent screen: External, Testing 모드 유지, scopes calendar.events.owned + calendar.readonly + openid email profile, Test users 등록
  4. Credentials → OAuth client ID: Web application, Name laminar-web, Redirect URIs:
    http://localhost:8080/api/auth/oauth2/callback/google
https://laminar-prod.fly.dev/api/auth/oauth2/callback/google
Testing 모드 유지 이유: 연구실 내부용이라 test user(≤100명) 충분. Production 전환 시 sensitive scope 앱 검증 필요. Trade-off: refresh token 7일 만료 → Phase 3 재인증 플로우.
콜백 경로 주의: /api/auth/oauth2/callback/google은 §11.2 지정 커스텀. Spring Security 기본값(/login/oauth2/code/google)과 다름 → Phase 3 명시 설정.
.env 기록 (2종): AUTH_GOOGLE_ID · AUTH_GOOGLE_SECRET
2.6Sentry✅
  1. sentry.io 가입 → Create Project: Platform Java → Spring Boot, name laminar-api
  2. SDK 매뉴얼 표시 — Phase 0에서 가져갈 건 DSN 하나뿐. 나머지(Gradle 플러그인·OpenTelemetry agent)는 Phase 1+ 코드 작업
  3. DSN 위치: 생성 화면 또는 Settings → Projects → laminar-api → Client Keys (DSN)
SENTRY_AUTH_TOKEN은 Gradle 플러그인 source context 업로드용 빌드타임 시크릿 — Fly secrets 대상 아님.
.env 기록: SENTRY_DSN · 정책: traces-sample-rate = 0.1 (Phase 1 application.yml)
2.7자체 시크릿 생성 (Task 0.7.1~0.7.4)✅

4종 각 32바이트 random → base64. 값을 stdout에 노출하지 않고 .env에 직접 기록:

F=/home/lsmin124/laminar/.env
for k in AUTH_SECRET APP_SECRET_V1 CRON_SECRET SAMPLE_MANAGER_HMAC_SECRET; do
  v=$(openssl rand -base64 32)
  sed -i "s|^${k}=.*|${k}=\"${v}\"|" "$F"
done
  • AUTH_SECRET — 세션 토큰 서명
  • APP_SECRET_V1 — envelope AES-GCM (버전드, 로테이션 시 _V2 추가)
  • CRON_SECRET — cron trigger 엔드포인트 인증
  • SAMPLE_MANAGER_HMAC_SECRET — SampleManager bridge HMAC

검증: 각 값이 44자(32바이트 base64).

Fly secrets 등록 .env 17개를 stdin으로 일괄 등록 (argv 노출 방지)

F=/home/lsmin124/laminar/.env
grep -E '^[A-Z]' "$F" | sed 's/="/=/; s/"$//' | fly secrets import --stage -a laminar-prod
  • grep -E '^[A-Z]' — 주석·빈 줄 제외
  • sed 's/="/=/; s/"$//' — 감싼 따옴표 제거
  • --stage — 배포 트리거 없이 스테이징 (첫 배포 시 VM 적용)

검증: fly secrets list -a laminar-prod → 17개 키 + digest, 값은 노출 안 됨

시크릿 로테이션 유출·정기 교체 시 절차

외부 서비스 키

R2 · Resend · Google · Sentry DSN

  1. 콘솔에서 새 키 발급 (기존 키 유지)
  2. .env 갱신
  3. fly secrets import --stage 재실행
  4. 배포 → 새 키 동작 확인
  5. 콘솔에서 기존 키 폐기

자체 시크릿

AUTH · CRON · HMAC

  1. 생성 스크립트 재실행 (openssl rand)
  2. .env 갱신 → fly secrets import
  3. AUTH_SECRET 교체 시 기존 세션 전부 무효화
  4. APP_SECRET_V1은 버전드 — 덮어쓰지 말고 _V2 추가 + 복호화 폴백 + 재암호화 마이그레이션

Neon DB 비밀번호

  1. Neon 콘솔에서 role 비밀번호 재설정
  2. DATABASE_USERNAME·DATABASE_PASSWORD 갱신
  3. fly secrets import → 배포

트러블슈팅 최초 셋업에서 실제 발생한 이슈

증상원인해결
fly: command not found flyctl 설치 후 PATH 미반영 (기존 셸은 .bashrc 수정 전 시작됨) ~/.local/bin/fly 심볼릭 링크 생성 (즉시 반영)
fly regions set nrt → "no longer supported" flyctl 0.4.x에서 deprecated 리전은 fly.toml의 primary_region으로
psql: command not found DB 클라이언트 미설치, sudo 없음 Neon 웹 SQL Editor로 citext 활성화. 접속은 TCP 도달 확인으로 갈음
.env 편집했는데 비어 보임 에디터 저장 타이밍 — 저장 직전에 읽음 잠시 후 재확인. 다른 경로 편집 여부 점검
R2_ENDPOINT에 <R2_ACCOUNT_ID> 그대로 템플릿 placeholder 미치환 실제 account ID로 치환
모든 fly 명령에 "Metrics token unavailable" flyctl의 알려진 무해한 표시 무시
Spring Boot 부팅 시 Driver claims to not accept jdbcUrl postgresql://... pgjdbc는 user:pass@host URL 인증 거부 + libpq channel_binding 인식 못함 .env URL을 jdbc:postgresql://host/db?sslmode=require로 변경 + USERNAME·PASSWORD 분리
